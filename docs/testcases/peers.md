# Тест-кейсы: Видимость блока «Сыграно с игроками» (Пиры)
> **Связанная диаграмма:** [Диаграмма видимости пиров](../diagrams/peers-visibility.md)  
> **Связанный автотест:** `tests/test_peers.py` (в разработке)

**Предусловия секции:**
1. Приложение доступно по адресу `http://45.86.245.140.nip.io/`
2. В системе есть минимум 2 пользователя: `User A` (авторизованный, имеет статистику и пиры) и `User B` (чужой профиль).
3. У `User A` в БД есть данные в таблице `peers`.
4. DevTools → вкладка Network открыта для отслеживания запросов.
5. Тест выполняется последовательно: 4 сценария.
6. Сценарии A, B, C, D соответствуют TC-PEERS-001...TC-PEERS-004

**Постусловия секции:**
- Сессия `User A` сохранена (в сценариях B, C, D1-D2).
- Данные в БД не изменены.
- Лимиты OpenDota не потрачены на сценарии A, C, D1, D3-D4.

---

## TC-PEERS-001: Гость смотрит любой профиль

**Приоритет:** High  

**Тип:** Негативный  

### Шаги
| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть сайт в режиме инкогнито (без авторизации) | Открывается главная страница, статус «гость» |
| 2 | Выбрать `User A` в списке слева | Загружается профиль `User A`, статистика отображается |
| 3 | Проверить блок «Сыграно с игроками» | **Блок не отображается** |
| 4 | DevTools → Network → фильтр `peers` | **Запрос к `/stats/{id}/peers` отсутствует** |
| 5 | Выбрать `User B` в списке слева | Загружается профиль `User B`, статистика отображается |
| 6 | Проверить блок «Сыграно с игроками» | **Блок не отображается** |
| 7 | Проверить Network → фильтр `peers` | **Запрос отсутствует** |

## TC-PEERS-002: Авторизованный смотрит свой профиль

**Приоритет:** High  

**Тип:** Позитивный  

### Шаги
| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Авторизоваться через Steam (`User A`) | Успешная авторизация, редирект на `/` |
| 2 | Убедиться, что открылся свой профиль | Заголовок показывает ник `User A` |
| 3 | Проверить блок «Сыграно с игроками» | **Блок виден**, отображается список пиров |
| 4 | DevTools → Network → фильтр `peers` | Запрос `/stats/{свой_id}/peers?limit=5` → **200 OK** |
| 5 | Кликнуть по логотипу (вернуться в свой профиль) | Блок пиров отображается, запрос снова уходит |

## TC-PEERS-003: Авторизованный смотрит чужой профиль

**Приоритет:** Medium  

**Тип:** Негативный  

### Шаги
| # | Действие | Ожидаемый результат |
|---|---|---|

| 5 | Вернуться в свой профиль (логотип) | Блок пиров снова виден, запрос уходит |

## TC-PEERS-004: Обход через прямой запрос к API


**Приоритет:** High

**Тип:** Негативный

**Предусловия:**

1. Пользователь авторизован как User A.
2. У User A есть данные в таблице `peers`.

**Шаги:**

| # | Действие                                                                             | Ожидаемый результат                          |
|---|--------------------------------------------------------------------------------------|----------------------------------------------|
| 1 | Открыть в новой вкладке прямой URL чужого профиля: `/stats/{чужой_id}/peers?limit=5` | Ответ **403** {"detail": "peers_forbidden"}` |
| 2 | Открыть в новой вкладке прямой URL своего профиля: `/stats/{свой_id}/peers?limit=5`  | Ответ **200**, JSON со списком пиров         |
| 3 | Разлогиниться (`/logout`)                                                            | Сессия очищена, редирект на`/`               |
| 4 | Открыть в новой вкладке: `/stats/{любой_id}/peers?limit=5`                           | Ответ **403** {"detail": "peers_forbidden"}` |

**Постусловия:**

- Сессия очищена (если был шаг 3).
