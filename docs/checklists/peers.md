# Чек-лист: Пиры (сокомандники)

**Модуль:** Пиры

**Приоритет:** Высокий

**Окружение:** Production / Local

## Отображение

- [ ] Блок «Пиры» НЕ отображается у гостя
- [ ] Блок «Пиры» НЕ отображается в чужом профиле
- [ ] Блок «Пиры» отображается в своём профиле авторизованного
- [ ] Для каждого пира отображается:
  - [ ] Ник
  - [ ] Аватар
  - [ ] Количество игр вместе
  - [ ] Винрейт вместе (WR)
- [ ] WR выделен цветом (≥50% зелёный, <50% красный)
- [ ] Сам игрок НЕ отображается в списке пиров
- [ ] Аватары загружаются (не битые)
- [ ] Отсутствующий аватар → заглушка

## Сортировка и лимит

- [ ] Сортировка по количеству игр (убывание)
- [ ] При равных играх — стабильный порядок
- [ ] Ограничение списка (топ-5)
- [ ] Если пиров больше лимита → показываются только топ-5

## Корректность данных

- [ ] Пиры считаются по **своей** команде (не враги)
- [ ] Пиры считаются по всем матчам 
- [ ] Винрейт = `wins / games * 100%`
- [ ] Количество игр = матчи, где игроки были в одной команде
- [ ] Данные совпадают с OpenDota (ручная сверка 2–3 пиров)
- [ ] Один и тот же пир не дублируется

## Пустые состояния

- [ ] У игрока нет пиров → пустое состояние
- [ ] OpenDota недоступна → ошибка или заглушка
- [ ] Профиль закрыт → «Нет данных»

## API

- [ ] `GET /profile/{id}/peers` → 200 OK для авторизованного (свой профиль)
- [ ] `GET /profile/{id}/peers` → 401 для гостя
- [ ] `GET /profile/{id}/peers` → 403 для авторизованного (чужой профиль)
- [ ] `GET /profile/{id}/peers` для несуществующего ID → 404
- [ ] Ответ — JSON-массив
- [ ] Поля: `account_id`, `nickname`, `avatar`, `games`, `winrate`
- [ ] `limit`: 1, 10, 100, 0, -1 → корректная обработка

## Граничные случаи

- [ ] 1 пир → список из 1 элемента
- [ ] 0 пиров → пустое состояние
- [ ] Длинный ник пира → не вылезает за карточку

## Что НЕ проверяем в этом чек-листе

- Доступ к блоку «Пиры» (покрыто в `profile.md`)
- Авторизация (покрыто в `auth.md`)
- Общая статистика (покрыто в `stats.md`)
