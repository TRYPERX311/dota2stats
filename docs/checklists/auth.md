# Чек-лист: Авторизация через Steam

**Модуль:** Авторизация

**Приоритет:** Высокий

**Окружение:** Production / Local(Не доступен в РФ)

## Вход

- [ ] Кнопка «Войти через Steam» отображается на главной для гостя
- [ ] Клик по кнопке → редирект на `steamcommunity.com/openid/login`
- [ ] Вход с валидными данными → редирект обратно на `/me`
- [ ] Вход с невалидными данными → уведомление об ошибке
- [ ] Новый пользователь → статистика загружается
- [ ] Существующий пользователь → статистика отображается

## Негативные сценарии

- [ ] Отмена авторизации в Steam → возврат гостем, сессия не создана
- [ ] Steam недоступен → ошибка, приложение не падает

## Сессия

- [ ] Перезагрузка страницы (F5) → сессия сохраняется
- [ ] Закрытие и открытие браузера → сессия сохраняется
- [ ] Новая вкладка → тот же пользователь
- [ ] Долгое бездействие → сессия истекает (если есть TTL)

## Выход

- [ ] Клик «Выйти» → редирект на главную
- [ ] После выхода кнопка «Войти» снова видна
- [ ] F5 после выхода → сессия не возвращается
- [ ] Прямой переход на `/me` после выхода → 401 или редирект
- [ ] Прямой переход на `/profile/{id}` после выхода → скрыт или 401

## Пиры (доступ)

- [ ] Пиры видны авторизованному пользователю в своём профиле
- [ ] Пиры **скрыты** для гостя
- [ ] Пиры **скрыты** для другого авторизованного пользователя
- [ ] API `/profile/{id}/peers` возвращает 401/403 без авторизации

## UI

- [ ] Для гостя видна кнопка «Войти»
- [ ] Для авторизованного кнопка «Войти» скрыта
- [ ] Для авторизованного видна кнопка «Выйти»
- [ ] Для авторизованного виден аватар и ник
- [ ] Аватар загружается (не битый)

## Граничные случаи

- [ ] Авторизация в Chrome и Firefox одновременно → один и тот же пользователь
