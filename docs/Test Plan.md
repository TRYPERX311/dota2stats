\# Test Plan — Dota 2 Stats



\## 1. Введение



\### 1.1. Цель документа

Описывает стратегию, объём, подход и ресурсы для тестирования веб-приложения Dota 2 Stats.



\### 1.2. Объект тестирования

Веб-приложение Dota 2 Stats — сервис для просмотра статистики игроков Dota 2 через OpenDota API.



\- \*\*Прод:\*\* http://45.86.245.140

\- \*\*Репозиторий:\*\* https://github.com/TRYPERX311/dota2stats

\- \*\*Стек:\*\* FastAPI, MySQL, Docker, GitHub Actions, HTML/CSS/JS



\### 1.3. Ссылки

\- Swagger / API docs: `http://45.86.245.140/docs` (в dev-окружении)

\- OpenDota API: https://docs.opendota.com



\## 2. Объём тестирования (Scope)



\### 2.1. В объёме (In Scope)

\- Авторизация через Steam OpenID

\- Просмотр списка пользователей

\- Профиль игрока (ранг, KDA, винрейт, W-L)

\- Статистика за последние 20 матчей

\- Статистика за текущий патч

\- Топ героев (за всё время и за патч)

\- Список сокомандников (пиры)

\- API-эндпоинты `/users`, `/stats/\*`, `/profile/\*`

\- Регрессионное тестирование после деплоя

\- Smoke-тестирование прода



\### 2.2. Вне объёма (Out of Scope)

\- Нагрузочное тестирование (не в приоритете для пет-проекта)

\- Тестирование безопасности (пентест)

\- Тестирование мобильных приложений (их нет)

\- Тестирование совместимости с IE / старыми браузерами

\- Локализация (только русский)



\## 3. Виды тестирования



| Вид | Применяется | Инструменты |

|---|---|---|

| Функциональное | Да | Ручное, pytest |

| API | Да | pytest, Postman |

| UI | Да | Playwright, ручное |

| Регрессионное | Да | pytest + смоук-чек-лист |

| Smoke | Да | Ручное (после деплоя) |

| Интеграционное | Да (OpenDota) | Ручное + mock |

| Нагрузочное | Нет | — |

| Безопасности | Нет | — |



\## 4. Подход к тестированию



\### 4.1. Уровни

1\. \*\*Ручное\*\* — исследовательское, UI, сценарии.

2\. \*\*Автоматизированное\*\* — API (pytest), UI (Playwright).

3\. \*\*CI/CD\*\* — автотесты на каждый push через GitHub Actions.



\### 4.2. Техники тест-дизайна

\- Классы эквивалентности (для параметра `limit` в API).

\- Граничные значения (для `limit`, `user\_id`).

\- Таблица решений (логика W-L).

\- Диаграмма состояний (авторизация).

\- Попарное тестирование (комбинации scope/position/limit).

\## 6. Критерии входа / выхода



\### 6.1. Критерии входа (Entry Criteria)

\- Код задеплоен на прод.

\- API доступен, возвращает 200.

\- Тестовые данные есть в БД.



\### 6.2. Критерии выхода (Exit Criteria)

\- Все запланированные тест-кейсы выполнены.

\- Критические и блокирующие баги закрыты.

\- Pass rate ≥ 90%.

\- Отчёт о тестировании подготовлен.



\## 7. Риски



| Риск | Вероятность | Влияние | Митигация |

|---|---|---|---|

| OpenDota API недоступна | Средняя | Высокое | Mock-данные |

| Steam OpenID недоступен | Низкая | Высокое | Тестовый пользователь |

| Прод недоступен | Низкая | Среднее | Локальный запуск через Docker |

| Внешние CDN (аватары, иконки) не отвечают | Средняя | Низкое | Не критично для тестов |
